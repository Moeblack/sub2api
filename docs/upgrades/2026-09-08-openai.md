## 必须保留的定制行为

- `call_id` 是工具调用与结果之间的关联值。原生 Responses 路径不擅自改写、截断或散列上游原始 ID，也不从另一种 item ID 猜出缺失的 call ID。
- 函数、自定义工具、工具搜索、命名的独立任务输出，以及加密压缩历史分别处理；不能因本地看不到历史，就删除合法工具结果。
- 延迟异步工具结果继续使用原始 `call_id`。空字符串工具结果也必须保留必需的 `output` 字段。
- 同一客户端缓存提示不能共享不同物理连接的临时历史。持久化响应续接需要通过用户/API Key 所有权校验。
- 旧兼容通路只在确认安全且当前轮尚未产生不可重放效果时重试当前轮，不重放旧轮次。原生多路连接不重放已写出或执行结果未知的请求。
- 公开 API Key 的独立 compact 协议与 OAuth 内部 compact 适配保持边界，保留完整压缩输出窗口及其中的不透明内容。
- 保留 Codex 模型目录中已有的 Ultra 工作流及独立的多代理元数据；它不是公开 Responses API 的 `reasoning.effort` 枚举值。Astra 公开 API 文档列出的是 `low` 至 `max` 五档。

## OpenAI 能力与边界

| 能力 | 本轮处理 | 使用边界 |
| --- | --- | --- |
| `reasoning.mode` / `reasoning.effort` | 在支持的原生模型上独立保留，避免把 `pro` 普遍改成 `max` | 模型和账号是否实际支持由目标上游决定；未知模型不套用旧模型规则 |
| `reasoning.context`、`configuration_update` | 保留字段及历史项顺序 | 必须使用原生 Responses；不能假装等价转换成 Chat Completions 或其他厂商协议 |
| 异步 function/custom 工具 | 保留工具与调用上的 `async`、迟到结果、原始 ID | 网关不替应用执行后台任务，也不把异步语义静默降级成同步 |
| 缓存选项与断点 | OpenAI 通路保留 `prompt_cache_options`、缓存保留设置和 `prompt_cache_breakpoint` | 其他供应商不能自动视为支持 OpenAI 字段 |
| `allowed_tools` 与命名空间 | 保留工具限制、工具身份和调用参数 | 不将限制误改为无限制的 `auto` |
| 原生 WebSocket 多路响应 | 每条物理连接独立状态；同 lane FIFO、不同 lane 并行；16 个执行中响应、32 个命名 lane | 仍受管理员配置、用户/账号并发额度、模型白名单和本机内存队列上限约束 |
| `response.steer` | 透传真正的 Steering，处理 accepted/pending/failed 与自动后继响应 | 不能用取消后重新生成来模拟；断线后不盲目重发已接受的输入 |
| `response.inject` | 原生通路透传并校验本连接目标响应 | 属于官方 SDK beta 参考中公开的协议，上游端点必须实际支持；不提供 HTTP 模拟 |

官方协议支持不等于某个 ChatGPT OAuth 内部端点已开放全部能力。没有可用的真实目标账号验证时，只能报告网关转发/状态机测试通过，不能报告上游账号能力已经实测。

分组推理策略会逐项检查明文 `configuration_update`。如果映射、降档或上限会改变已存在的历史项，明确拒绝请求，而不是重写旧历史或缓存前缀。日志优先采用最后一个可见更新中的 effort；只有 `previous_response_id`、看不到服务端继承配置时，仍是请求档位估计。官方返回的 `response.reasoning.effort` 也不能作为动态更新后实际档位的证明。管理员改变策略后，对不可见的既有历史不宣称已经完成全量约束验证。

### 选择原生 WebSocket

普通客户端保持原有模式。需要 Steering 或原生多路能力的客户端，在 WebSocket 握手中发送：

```http
X-Sub2API-WebSocket-Mode: native
```

管理员必须启用 OpenAI WebSocket v2 和模式路由，并提供设置为 `passthrough` 的可用账号。客户端请求不能覆盖全局禁用、强制 HTTP 或账号关闭设置。不符合要求时应显式拒绝，不能静默切换为语义不同的 HTTP 桥接。

`stream_id` 与 `previous_response_id` 是不同概念：前者选择执行队列和事件归属，后者指定历史父响应。Steering 按父响应定位，不在控制帧中另加 `stream_id`。复用客户端 session/cache 提示不代表复用另一条物理连接的未持久化历史。

原生路径不自动重连重放。若连接在写请求、执行工具或接受 Steering 后中断，客户端须先核对结果；错误文本不能作为“之前没有执行”的证明。

`generate:false` 且确实没有生成输出/用量的预热不进入按次收费，也不当作模型成功推理来提升账号健康统计。如果上游违背预热参数实际生成输出或报告用量，仍按真实执行记录处理。

## 发布前验收

以下为本轮验收范围；尚未运行或条件跳过的检查不计为通过。

1. 后端完整 unit 测试与隔离 PostgreSQL/Redis 集成测试。
2. 历史输入语义、工具身份、任务委派、孤立工具结果、压缩续接、跨连接/跨用户所有权、失败重试回归。
3. 原生 WebSocket 多 lane 交错事件、顺序队列、16/32 限额、Steering 后继响应、pending 后工具续接、异步注入与断线不重放。
4. 每个响应的并发槽、用量、推理档位、图片计数、模型映射和审计独立；重复/迟到终止事件不能重复结算或结算其他响应。
5. 原始重复 JSON 路由字段、模型白名单与 warmup 的拒绝路径，保证未授权请求不执行、不计费。
6. 协议关键路径 race 检查与输入语义 fuzz 种子/有界 fuzz 检查。
7. 前端完整测试、i18n 检查、类型检查和生产构建；新的 Linux 二进制版本、校验和、隔离启动及内嵌界面验证。

## 数据库与回滚

迁移 235/236 将旧 `models_list_config` 配置迁移为 `model_allowlist` 并修复配置，必须验证启用、禁用、空配置等旧数据。迁移 237 增加 MiniMax 相关默认配置；其他完整合并中的迁移也不能跳过。

旧二进制仍读取旧列，因此升级数据库以后不能只切回旧镜像。生产切换前应准备经过验证的兼容回滚构建或逆向迁移，并先排空长连接。不得在新版本已经产生业务写入后，直接恢复升级前备份而丢弃这些写入。

本轮开发和集成测试使用隔离资源，不修改生产数据库，不在未经说明的情况下更新生产镜像。
